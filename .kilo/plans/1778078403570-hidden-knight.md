# Fix JobBoard Kanban Horizontal Scroll & Header Buttons Visibility

## Goal
Resolve two issues on `/jobs` page:
1. Horizontal scroll bar does not appear, preventing viewing all Kanban columns.
2. Top‑right toggle (Kanban/Lista) and “Nova Vaga” button are hidden/missing after render.

## Root‑Cause Analysis
- Kanban container uses `display: inline-flex` but lacks `overflowX: 'auto'` on the correct element and child columns can shrink/collapse; `white-space: nowrap` is not set, so when total column width ≤ viewport width the horizontal scroll disappears (browser may not show scrollbar because space is available).
- Header row uses `position: absolute` inside a parent with `borderBottom` and `paddingBottom`; the parent’s height is driven by content but the absolute container is positioned relative to it. If the parent’s height collapses or the absolute container is pushed out of flow, buttons may not be visible.
- Parent layout (`.main-content` in `MainLayout.tsx`) has `overflow: 'hidden'` and `flex: 1` — this can clip absolutely positioned children if they extend beyond the flex container.
- JobBoard root has `height: '100%'` and `width: '100%'` but no enforced `minHeight` on the content area, so on small viewports the header/action area may be compressed or hidden.
- `display: inline-flex` on the Kanban wrapper may allow line wrapping in some browsers when combined with flex layout from parent, causing vertical expansion and hiding horizontal overflow.

## Detailed Findings
1. **MainLayout `.main-content`**: `overflow: 'hidden'` will clip any absolutely positioned element that overflows this box. Since JobBoard header uses absolute positioning for the top‑right group, if the header’s natural height is small and the absolute container sits at `top:0; right:0`, it is contained — but if the parent’s own height collapses or flexbox sizing pushes content, the area can be clipped.
2. **JobBoard header** (`<div style={{ position: 'relative', … }}>`) — absolute container for toggle/button is sized by content; it should remain visible unless overflow hidden is applied.
3. **Kanban container** (`key="kanban"`) styles (lines 146–150):
   ```tsx
   style={{
     display: 'inline-flex',
     gap: '1rem',
     height: '100%',
     paddingRight: '2rem'
   }}
   ```
   Missing: `overflowX: 'auto'` and `whiteSpace: 'nowrap'`. Without these the container may not scroll horizontally.
4. **Column divs** (lines 163–173) have `flexShrink: 0` and `width: '300px'`. That’s fine, but if parent has no `min-width` enforcement or `white-space: nowrap`, browser may still allow flex shrinking.
5. **Parent of Kanban** (`<div style={{ height: '100%', width: '100%', overflowX: 'auto', overflowY: 'hidden' }}>` on line 109) — this already has horizontal scroll, but the inner `inline-flex` must not allow wrapping.

## Implementation Details
- **Step 1** – Kanban container (line ~146):
  ```tsx
  style={{
    display: 'inline-flex',
    gap: '1rem',
    height: '100%',
    paddingRight: '2rem',
    overflowX: 'auto',      // ensure scrollable
    whiteSpace: 'nowrap'    // prevent wrapping of inline-flex children in some contexts
  }}
  ```
- **Step 2** – Column div (line ~163):
  ```tsx
  style={{
    width: 300,
    flexShrink: 0,
    display: 'flex',
    flexDirection: 'column',
    gap: '1rem',
    minWidth: 300
  }}
  ```
- **Step 3** – Parent of Kanban (line ~109) — already has `overflowX: 'auto'`, keep. Check that it doesn’t have `overflowY: 'hidden'` conflicting with vertical behavior (it’s fine).
- **Step 4** – Header (line ~65):
  ```tsx
  style={{
    position: 'relative',
    width: '100%',
    borderBottom: '1px solid var(--border)',
    paddingBottom: '1rem',
    minHeight: 58,
    display: 'flex',
    alignItems: 'center'
  }}
  ```
- **Step 5** – MainLayout `.main-content` (line ~93): change `overflow: 'hidden'` to `overflow: 'visible'` or remove. Since other pages may rely on clipping, a safer override is to set `overflow: 'visible'` only when inside JobBoard via a wrapper, but easier is to update MainLayout because `hidden` is likely too aggressive for all pages. If unsure, we can scope with a CSS utility class, but for simplicity we can change to `overflow: 'visible'` and test routes.

## Risks & Mitigations
- **Risk**: Changing `overflow: 'hidden'` to `visible` on `.main-content` may cause unwanted overflow in other pages (modals, dropdowns).
  - **Mitigation**: Test all main routes after change. If issues appear, scope the override to JobBoard only (add a wrapper div with `overflow: visible` or use a CSS class).
- **Risk**: `whiteSpace: 'nowrap'` on an `inline-flex` container may have no effect in some browsers (since `white-space` applies to block containers). Instead, ensure the parent of the inline-flex container has `overflowX: auto` and `white-space: nowrap` on that parent if needed.
  - **Mitigation**: Primary control is `overflowX: auto` on the scroll container; `whiteSpace: nowrap` on the parent of the columns (the inline-flex wrapper) can help prevent wrapping in edge cases.
- **Risk**: Absolute-positioned header buttons may overlap column content on very narrow screens.
  - **Mitigation**: Ensure header has a `z-index` (already has `zIndex: 500` on the toggle container) and the header row has enough `minHeight` to contain content.
