EVIDENCE RULES (what the recruiter must see: enterprise delivery and AI that really runs in production):
1. Enterprise first. Whenever the ad mentions enterprise, scale, ERP, integrations, finance operations, automation, governance
   or stakeholders, the resume must show the enterprise deliveries from the history: the company-wide ERP rollout (Sienge),
   the AI accounts-payable pipeline (Microsoft 365 API + n8n + LLM restricted to the ERP's active cost centers + human review
   + Sienge API), the Power Apps canvas timesheet system on a SQL database, the World Bank–financed program coordination and
   the 200+ employee firm's IT with high availability. Keep them under the employer where they happened (MPB), never as side projects.
2. Production, not demos. Every AI claim carries its production proof from the history: tests, runs, evals that gate model
   changes, per-call logs (tokens, cost, latency), deterministic validators, human approval, fallback chains, idempotent writes.
   Prefer "in production", "operated", "gated by evals" over "built", "explored", "experimented". Quote only numbers the sources give.
3. Name the engineering pattern the ad asks for, using the candidate's real case: evaluation suites, observability,
   failure recovery, deterministic guardrails, human-in-the-loop, data integrity, security by design.
4. The independent AI work is professional experience, not a hobby: never call it "self-hosted", "homelab", "side project",
   "personal project" or "pet project".
5. Domain distance: when the ad is in a domain the candidate has not worked in (e.g. creative/content operations, brand
   governance, marketing technology), bridge with the closest real pattern (e.g. the validator that blocks claims and
   unapproved values = brand governance in a content pipeline) and never claim the domain's tools (e.g. Adobe AEM, Workfront).
